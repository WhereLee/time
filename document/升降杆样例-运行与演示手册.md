# 升降杆样例——运行与演示手册

一个"十公里外的杆"的完整控制闭环：平台（reason-main）+ 设备模拟器（reason-barrier-sim）双进程，覆盖台账、指令、事件、心跳、自动规则、超时对账、故障告警、防砸互锁全部机制。

## 环境要求

- JDK 17、Maven、MySQL（reason_faster 库）、Redis（**db15**，框架配置）
- **RocketMQ 三进程**（事件通道终态默认走 MQ）：namesrv 9876 / broker 10911 / proxy 8081——启动见 `document/block-records/MQ-ENV-NOTES.md`
- 依次导入 `db/reason-faster.sql`（框架基线）→ `db/02-barrier-device-record.sql`（台账+菜单）→ `db/03-barrier-full-loop.sql`（流水/告警表+Quartz 任务注册+权限）→ `db/04`…`db/09`（协议v2/阶段0残留/量级索引/任务看护/保留清理/毫秒迁移；文件名序=依赖序，全部幂等）
- **Redis 为手动启动进程（非 Windows 服务）**：机器重启后须手动拉起，否则平台 Lettuce 超时风暴；另若 Redis 加载了旧 dump（seq 计数器回退），自动对账会撞流水唯一索引 `u_device_seq` 而每轮静默跳过（WARN 级）——排查：`redis-cli -n 15 get barrier:cmd-seq:{deviceNo}` 与 `SELECT MAX(command_seq) FROM device_command_log` 对不上即中招

## 启动（顺序：平台 → 模拟器）

```powershell
# 1. 平台（8200，context-path=/api）——T16 起必须显式 profile：无 profile 会因缺数据源 fail-fast（预期，不是故障）
cd inteink-faster\reason-main; mvn spring-boot:run "-Dspring-boot.run.profiles=dev"

# 2. 模拟器（8300，仅绑 127.0.0.1；事件通道默认 mq——终态，批次3 落档）
cd inteink-faster\reason-barrier-sim; mvn spring-boot:run
```

> 2 台形态的设备密钥经环境变量注入（`BARRIER_E01_SECRET` / `BARRIER_W02_SECRET`，与平台 `device_record.device_secret` 同值）；50 台形态用 `batch-secrets.properties`（见批量节）。

> **事件通道三态（批次3 落档）**：默认 `sim.event-channel=mq`（仅 MQ，HTTP 事件退役为降级开关）。需 HTTP 通道参与时改启动参数：对照/注入剧本用 `--sim.event-channel=dual`（双写，同 traceId 两路径可对照）；无 MQ 环境回滚用 `--sim.event-channel=http`。心跳恒 HTTP、下行指令恒 HTTP，不受开关影响。

启动即自动发生：模拟器**上电自述**（心跳通道校正平台台账）→ 平台 Quartz 加载 job 200/201 → `barrierAutoTask` 每分钟对账（白天窗口 08:00-18:00 内自动升杆）→ `barrierMonitorTask` 每 30s 超时/离线扫描。

登录：`POST /api/sys/login {"loginname":"adminManager","password":"admin123"}`，后续请求带 header `token`。连续 5 次密码错误会触发账号限时锁定（T19，5 分钟；本地解锁：`redis-cli -n 15 del login:lock:acct:<loginname>:127.0.0.1`）。

## 演示剧本（每个边界怎么触发）

| 演示 | 操作 | 观察点 |
|------|------|--------|
| 自动升降 | 什么都不做，等整分 | main 日志 `自动对账发现偏差 ... 下发校正指令 OPEN`；台账 state 变化 |
| 手动闭环 | `POST /api/device/command/open {"deviceNo":"BARRIER-E-01"}` | 3s 内 state 2→3→1；流水 PENDING→ARRIVED |
| 防连点 | 1 秒内连发两次 open | 第二次 `操作过于频繁`（@RepeatGuard） |
| 手动保持期 | 手动指令后看 Redis | `barrier:manual-hold:{no}`=userId TTL 30min；期间 autoTask 日志 `让位` |
| 防砸互锁 | `POST :8300/sim/vehicle {"deviceNo":"...","present":true}` → 平台 close | close 被拒 `杆下有车`；流水 SEND_FAILED |
| 卡杆故障 | `POST :8300/sim/fault` → 平台 open | state→4(FAULT)；告警 type=4；流水 EXEC_FAILED；再发指令被拒 `故障中` |
| 人工复位 | `POST :8300/sim/recover` | state→2；DOWN 事件上报 |
| 外力改态 | `POST :8300/sim/tamper {"state":"UP"}` | 台账被设备自述校正（非指令驱动） |
| 断电恢复 | 直接重启 sim 进程 | 上电自述→平台 `心跳对账发现状态漂移` 校正+告警 |
| 离线判定 | 停 sim 等 35s | 台账 online=false；告警 type=2；Redis online key 过期 |
| 事件丢失+重试幂等 | sim yml `event-url` 改错地址重启 + 平台 `command-timeout-seconds: 10`、`max-retry: 1` 重启 | 心跳兜底校正台账；monitor `经台账对账确认已到位，销账`（若台账未到位则重试同 seq→超限告警） |
| 设备侧快照 | `GET :8300/sim/status` | 物理真相（state/faultInjected/vehiclePresent）vs 平台台账快照 |

## 接口清单

**管理端**（token + 权限）：
- `GET /api/device/record/list`（device:record:list，含 online 实时字段）
- `POST /api/device/record/save`（device:record:save）
- `POST /api/device/command/open|close`（device:command:open|close，@RepeatGuard+@ManualHold+@SysLog）
- `GET /api/device/alarm/list`（device:alarm:list）
- `GET /api/device/commandlog/list`（device:commandlog:list）

**设备通道**（per-device HMAC：`X-Device-No` + `X-Device-Sign`，白名单免登录；共享口令 X-Device-Token 已随 0.5 退役）：
- `POST /api/device/event` {deviceNo, state, commandSeq, bootId, eventSeq}——状态事件（协议v2；台账唯一合法写入口）
- `POST /api/device/heartbeat` {deviceNo, state}——心跳（TTL 续命+对账；state 可空=只报活）

**模拟器**（仅 127.0.0.1）：
- `POST /cmd` {deviceNo, action, commandSeq}——平台指令入口（code=0 受理/幂等忽略，code=1 拒绝）
- `POST /sim/fault|recover|tamper|vehicle`、`GET /sim/status`——物理世界注入口

## 配置速查

平台 `reason.barrier.*`：auto-enabled / auto-open-time / auto-close-time（支持跨午夜）/ heartbeat-timeout-seconds=30 / command-timeout-seconds=60 / max-retry=3 / manual-hold-minutes=30 / reconcile-grace-seconds=3 / alarm-dedup-seconds=300

模拟器 `sim.*`：event-url / heartbeat-url / heartbeat-interval-seconds=10（须小于平台超时阈值）/ event-channel=mq|http|dual / move-millis=3000 / devices[]（deviceNo 与平台台账对齐；secret 环境变量注入=同平台 device_secret）

## 状态与类型码

- 设备状态：0-未接入 1-升起 2-降下 3-动作中 4-故障（台账状态**只信设备上报**，指令侧/任务侧禁改）
- 指令流水：0-待到位 1-已到位 2-下发失败 3-重试超限 4-执行失败(设备故障) 5-被更新指令取代；触发源：1-手动 2-自动规则 3-超时重试
- 告警类型：1-重试超限 2-离线 3-对账不一致 4-设备故障 5-自动校正连续失败 6-动作卡死未到位 7-批量离线 8-任务停摆 9-对账持续异常

## 批量（50 台）形态（批次2，2026-09-09）

同进程**配置驱动生成式**注册 50 台虚拟杆（`BARRIER-B-01…50`，心跳并行 16 线程），验证量级适配：scanOffline pipeline 批量在线判定、markOnlineRecovered Redis 标记门控、告警 DB 查重索引。日常 2 台形态零改动（`sim.device-count` 缺省 0 = 显式 devices 清单；>0 = 完全生成式，显式列表忽略）。

### 批量启动（登记 → 密钥文件 → batch profile）

1. **登记 + 密钥文件一次性产出**（50×32hex 强随机密钥；平台 `deviceSecret` 与 sim 密钥文件同源闭环）：
   - 循环调 `POST /api/device/record/save`（body 带 `deviceSecret`，`^[0-9a-f]{32}$`）50 次；
   - 同一次运行把 `deviceNo=hex` 写入 `reason-barrier-sim/batch-secrets.properties`（**gitignore，仓库零明文**；文件缺失 sim 启动 fail-fast，缺行 fail-safe 不上报）。
2. **sim batch 启动**：
   ```powershell
   cd inteink-faster\reason-barrier-sim; mvn spring-boot:run "-Dspring-boot.run.profiles=batch"
   ```
3. 观察：`GET :8300/sim/status` 返回 50 台；平台台账 50 台 online=true（Redis db15 `barrier:online:*`）；每台 10s 心跳节拍不塌（16 线程池）。

### /sim/network 批次2 新参数（仅 HTTP 事件通道；MQ 通道不受注入）

| 参数 | 语义 |
|---|---|
| `eventDelayMillis` | 事件发送前人为延迟（0 关；打心跳对账 grace=3s 边界） |
| `replayNextEvent` | 下一条**成功送达**的事件同报文重发 1 次（一次性；失败不消费布防） |
| `reorderDeviceNo` | 该设备两条事件**集齐后按 eventSeq 降序发送**（一次性；仅 1 条超时 5s 原序放行） |

### G1-G3 剧本命令摘要（证据见 block-records/批次2 实施记录）

- **G1 启动稳定**：登记 50 台 → batch 启动 → 稳定 ≥2 分钟：零 OFFLINE/对账告警、心跳不塌、台账校正正确。
- **G2 事件洪峰**：10 台/组 × 5 组 × 2 轮（OPEN→等全 UP→CLOSE→等全 DOWN）= 100 条手动指令 / ≥200 事件。注意：`@RepeatGuard` 按“操作者+方法”3s 防连点，批量脚本须每次发前清 Redis `rg:*` 键（等价独立终端语义）；`@ManualHold` 30min 让自动对账自动让位。断言：流水终态全 ARRIVED、任务轮次 <30s 周期。
- **G3 注入器三连**：`reorderDeviceNo`（乱序：HTTP 倒序补发被平台序守卫拒，流水只销一次）→ `replayNextEvent`（重放幂等吸收）→ `eventDelayMillis` 2000/5000（事件迟到仍受理；5s 场景心跳相位未命中则无 STATE_MISMATCH——标定边界 3s 结论不变，留档不调参）。

## 通道终态与量下回归（批次3，2026-09-10）

**终态落档**：事件通道默认 `mq` 单通道（D-A）——HTTP 保留为降级/对照开关（三态零代码切换，见上部启动节注）。落档依据：50 台量下回归四场景全过 + dual 双路径对照一致。

### 量下回归四场景（脚本骨架见工作区 `_g4_s*.ps1`；证据见 block-records/批次3 实施记录）

| 场景 | 操作 | 断言与实测 |
|---|---|---|
| S1 心跳延迟 | `/sim/network {heartbeatDelayMillis:3000}`（全场）+ 10 台 OPEN | 有效节拍 13s < 30s 阈值：online 保持 50、零 OFFLINE；10 台事件照常闭环 |
| S2 事件延迟+丢包 | `{eventDelayMillis:2000, dropNextEvent:true}` + 10 台 CLOSE | 丢包经重试/双写吸收：10 台全 ARRIVED、PENDING=0、零告警（2s < grace 3s） |
| S3 单向断 60s | `{blockUpstream:true}` 60s + 期间 10 台 OPEN | 断期 PENDING=0（HTTP 断、MQ 路径闭环）；50 台 OFFLINE 告警（预期集合）；恢复 15s 内在线恢复+告警自动全关、零残留 |
| S4 broker 故障 | 停 broker → 10 台 CLOSE → 重启 broker | 断期 HTTP 路径闭环（PENDING=0）；恢复后 sim 队列补发 + 平台消费幂等吸收；无 RETRY_EXCEEDED |

### 环境前置检查（惨痛教训）

1. Redis 手动启动（非服务）——机器重启后先拉起（`F:\Redis\redis-server.exe`）；加载旧 dump 会让 seq 回退→对账撞唯一索引静默卡死（现象：台账不校正、warn.log 每轮 `Duplicate entry`；修复：把 `barrier:cmd-seq:{deviceNo}` 对齐 `SELECT MAX(command_seq)`）。
2. MQ 三进程按 MQ-ENV-NOTES 起；broker 重启后 proxy 自动重连（实测 ~20s）。
3. 剧本发送手动指令前清 `rg:*`（防连点 3s 窗）；剧本动作天然带 30min 手动保持期让自动对账让位。

## 告警治理与任务看护（批次4，2026-09-10）

**风暴限速（D-F，双机制互补）**：
- 批量离线合并：单轮扫描离线数 ≥ `offline-batch-threshold`（默认 3）→ 只落 1 条 `BATCH_OFFLINE`（device_no=`__batch__`，content 含台数+前 20 台清单）；离线数回落低于阈值时由扫描自动关闭（谁开谁关）
- 滑动窗口限速：去重之上的第二道闸，per-type 全局 ZSET 窗口（`alarm-rate-window-seconds`=60 / `alarm-rate-max-per-window`=10），超限只记 warn 日志不落库（限速跳过会回滚去重占位，两机制正交）

**任务看护（job 202 `barrierTaskWatchdogTask`，每分钟第 10 秒）**：
- 数据源=schedule_job_log（log_state=0 的 MAX 时间，不改动通用 Quartz 框架——任务执行历史本就是它的记录）
- 判据=最后成功时间错过 `job-stall-missed-triggers`（默认 2）次 cron 触发；周期从 job_cron 动态解析（改 cron 阈值自动跟随）；基线 max(lastOk, 平台启动时刻)（重启宽限）
- 看护对象=启用的 barrier 家族任务（新增任务自动纳入，排除自身）；停摆 → ERROR 日志 + `JOB_STALLED`（device_no=`__job:{jobId}__` 每任务独立去重键）；恢复下一轮自动关
- 价值面：能发现“数据库说启用、实际没跑”的漂移（管理端 pause=已知停机不算，停摆看护只管未预期停摆）

**恢复标记完善（批次4 剧本发现并修复）**：
- 设备已到位（实然=应然）时解除历史熔断态并关闭 `AUTO_CORRECT_FAILED` 残留（静默恢复场景：外力到位/心跳对账归位后不再下发，窗口翻不了新）
- 离线设备前置跳过（离线时发不了指令、无从评估熔断——旧顺序会每窗口重复喊“校正失败”，且离线设备永远无法靠下发产生新 ARRIVED 解除熔断）

**对账连续异常升级（批次3 遗留归并）**：单台连续 N 轮（`reconcile-fail-streak-threshold`=5）处理异常 → `RECONCILE_ERROR`；成功轮清计数并关告警（严格连续语义：抓持续坏不抓偶发抖；告警摘要截断至 200 字符防超列长）

**业务指标端点（D-D 第 0 档）**：`GET /api/device/metrics`（权限 device:record:list，与设备台账同一只读视图）
- 返回：commandPending（PENDING 积压）/ deviceOnline / deviceProvisioned / onlineRate / unhandledAlarms / barrierTasks[]（jobId + state + lastSuccessAgoSeconds）

**db/07-barrier-stage4.sql**：job 202 注册（'10 * * * * ?' 与 200/201 错开）+ alarm_type 注释同步 1-9；本地/CI 幂等可重复执行

**剧本骨架**：工作区 `_g4b_p1..p4/verdict.ps1`；证据见 block-records/批次4 实施记录。

## 横切治理与毫秒化（批次5，2026-09-10）

- **启动纪律（T16）**：平台必须显式 profile；无 profile=数据源缺失 fail-fast（因日志兜底已能显示原因）。prod 凭据=`jasypt ENC()`（仓库内为演示密文，云上重新生成——见部署手册）
- **登录防护（T19）**：账号×IP 组合锁（`sys_param.attempt_limit=5` / `lock_time=5` 分钟）+ IP 维度闸（`reason.security.login-ip-max=20` / 600s）；`X-Forwarded-For` 仅在 `reason.security.trusted-proxies` 可信来源才解析（默认空=忽略一切代理头，伪造不绕过）
- **上行入口限流（批次5）**：Redis 令牌桶——per-device 5rps/burst10（心跳与事件共用）+ 全局水位闸 100rps/burst200（超限拒事件；心跳=判活生命线豁免全局闸）
- **审计降级**：`reason.audit.query-log-enabled=false`（默认）——GET 查询不写 sys_log，写操作仍全量审计
- **表保留清理**：job 203（每日 03:30；`reason.retention.*` 默认 90 天/500 行每批）——device_alarm/device_command_log 毫秒 cutoff、sys_log 秒级 cutoff（双时域）
- **毫秒化（D-H）**：device_record/device_command_log/device_alarm 六列全毫秒（存量迁移 `db/09`，幂等）；sys_log/schedule_*/manual_hold 保持秒级
- **回归剧本**：工作区 `_g5_s1..s8.ps1`（配置扫描/XFF爆破/限流/审计降级/清理/毫秒闭环/jasypt闭环/fail-fast），证据 `_g5_s*_out.txt`
