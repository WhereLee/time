# 云服务器部署手册（升降杆样例 · 单机全量复现）

> 目标机：Ubuntu 24.04 / 4G 内存 / Java 17（已在 124.223.36.154 同构机验证过前身形态）
> 部署形态：单机六进程 = MySQL + Redis + RocketMQ 三进程（namesrv/broker/proxy）+ reason-main（:8200）+ reason-barrier-sim（:8300）
> 事件通道：RocketMQ 默认（HTTP 为降级开关，见 §6 三态切换）；心跳/下行指令恒 HTTP
> 配置外部化（/opt/reason/config/）+ Jasypt ENC 凭据闭环（解密口令仅环境变量）

## 1. 端口与暴露面

| 组件 | 端口 | 暴露面 |
|---|---|---|
| reason-main | 8200 | 管理端入口（ufw 放行或经 nginx 反代） |
| reason-barrier-sim | 8300 | 进程绑 127.0.0.1，ufw 不开放 |
| RocketMQ namesrv / broker / proxy | 9876 / 10911 / 8081 | 仅 127.0.0.1 |
| MySQL / Redis | 3306 / 6379 | 仅 127.0.0.1（另见 §10 安全清单） |

内存预算（total 3.6Gi，另 1.9G swap 兜底；启动后 `free -m` 复核 available）：
系统地板 ~600M + MySQL ~400M + Redis ~15M + MQ 三进程 ~1.5G（按 §3.2 调小后）+ main ~700M + sim ~350M。
全组件上线后 available 若低于 300M，优先降 broker 堆（512m→384m）。

## 3. 部署步骤

### 3.1 中间件

```bash
sudo systemctl enable --now mysql redis-server
```

Redis 若设 requirepass：密码进 §3.4 的 Jasypt 密文同源处理。

### 3.2 RocketMQ 三进程（5.3.1，与本地开发同版本）

1）下载解压：

```bash
cd /tmp
wget https://archive.apache.org/dist/rocketmq/5.3.1/rocketmq-all-5.3.1-bin-release.zip
unzip rocketmq-all-5.3.1-bin-release.zip && mv rocketmq-all-5.3.1-bin-release /opt/reason/rockets
mkdir -p /opt/reason/rockets/logs
```

2）**JVM 调小（4G 机器必做）**——发行版默认按大内存机器配置，不调直接启动失败：

| 脚本 | 默认 | 改为 | 影响进程 |
|---|---|---|---|
| `bin/runserver.sh` | -Xms4g -Xmx4g -Xmn2g | -Xms256m -Xmx256m -Xmn128m | namesrv + proxy（proxy 复用此脚本） |
| `bin/runbroker.sh` | -Xms8g -Xmx8g，直接内存 15g | -Xms512m -Xmx512m，MaxDirectMemorySize=256m | broker |
| `bin/tools.sh` | -Xms1g -Xmx1g | -Xms256m -Xmx256m | mqadmin 等工具 |

（替代法：不改脚本，启动时经 `JAVA_OPT_EXT="-Xms256m -Xmx256m"` 环境变量覆盖——脚本把它追加在默认值之后，后出现的参数生效。）

3）broker 配置 `conf/broker.conf` 追加（固定注册回环，避免换网后注册地址失效）：

```
brokerIP1=127.0.0.1
```

4）proxy 配置 `conf/proxy.json`（JSON 格式，非 properties）：

```json
{ "rocketMQClusterName": "DefaultCluster", "grpcServerPort": 8081, "remotingListenPort": 0 }
```

5）启动（顺序：namesrv → broker → proxy）：

```bash
cd /opt/reason/rockets
nohup sh bin/mqnamesrv > logs/namesrv.out 2>&1 &
nohup sh bin/mqbroker -n 127.0.0.1:9876 -c conf/broker.conf > logs/broker.out 2>&1 &
nohup sh bin/mqproxy -pm cluster -n 127.0.0.1:9876 -pc conf/proxy.json > logs/proxy.out 2>&1 &
```

6）topic 显式创建（5.x 默认不自动建；单读写队列=事件全局有序前提）：

```bash
sh bin/mqadmin updateTopic -n 127.0.0.1:9876 -t device-event -c DefaultCluster -w 1 -r 1
```

7）验证：`jps` 见三名进程；`sh bin/mqadmin clusterList -n 127.0.0.1:9876` 见 broker 注册；`topicRoute -t device-event` 见 readQueueNums=1。

> **机器重启后 MQ 三进程不自启**（样例形态用 nohup 托管，未纳入 systemd）——先手动拉起再依赖 main/sim 的心跳与消费。

### 3.3 建库与导入 SQL

1）建库与账号：

```sql
CREATE DATABASE reason_faster DEFAULT CHARSET utf8mb4 COLLATE utf8mb4_general_ci;
CREATE USER 'reason_app'@'localhost' IDENTIFIED BY '<随机强密码>';
GRANT ALL PRIVILEGES ON reason_faster.* TO 'reason_app'@'localhost';
```

2）按文件名序导入（依赖序；全部幂等，可重跑）：

```
db/reason-faster.sql            # 框架基线（RBAC/Quartz/系统表）
db/02-barrier-device-record.sql # 设备台账 + 菜单
db/03-barrier-full-loop.sql     # 流水/告警表 + job 200/201 + 权限
db/04-barrier-protocol-v2.sql   # 协议 v2（bootId/seq 守卫）
db/05-barrier-stage0-rest.sql   # 阶段0 残留
db/06-barrier-batch-scale.sql   # 告警查重索引
db/07-barrier-stage4.sql        # job 202（任务看护）+ 告警类型注释
db/08-barrier-stage5.sql        # job 203（保留清理）+ 清理索引 + attempt_limit 迁移
db/09-barrier-stage5-millis.sql # D-H 存量毫秒化（幂等：<1e10 ×1000）
```

```bash
mysql -ureason_app -p reason_faster < db/<文件名>.sql   # 依次执行
```

- JDBC 连接串须带 `allowPublicKeyRetrieval=true`（MySQL 8 caching_sha2 + TCP）
- 09 为存量迁移，新库空表执行无害（条件不命中）

### 3.4 密钥与凭据生成

1）设备密钥（per-device HMAC，每台 32hex，两台）：

```bash
openssl rand -hex 16   # 执行两次：BARRIER-E-01 / BARRIER-W-02 各一枚
```

2）Jasypt 密文（数据库密码、Redis 密码；在构建机生成，密文可安全传输）：

```bash
java -cp ~/.m2/repository/org/jasypt/jasypt/1.9.3/jasypt-1.9.3.jar \
  org.jasypt.intf.cli.JasyptPBEStringEncryptionCLI \
  input=<明文密码> password=<JASYPT_ENCRYPTOR_PASSWORD> \
  algorithm=PBEWITHHMACSHA512ANDAES_256 ivGeneratorClassName=org.jasypt.iv.RandomIvGenerator
```

- 解密口令写 `config/main/reason-main.env`（600），绝不落仓库/落文档
- 仓库 application-prod.yml 中的 ENC 为**演示密文**（明文=root），云上必须用自己的口令重新生成
- 生成参数必须与 `application.yml` 的 jasypt.encryptor 四段参数一致（algorithm/迭代/盐/IV）

3）设备登记：平台台账 `device_record.device_secret` 写入同值密钥（管理端 save 接口带 deviceSecret，或 SQL）。

`config/main/application-prod.yml`（只写覆盖项，与 jar 内配置合并）：

```yaml
spring:

    druid:
      username: ENC(<密文>)
      password: ENC(<密文>)
  data:
    redis:
      password: ENC(<密文>)

# reason.security.trusted-proxies: ""      # 有 nginx 时填 127.0.0.1，否则忽略一切代理头

# reason.device.traffic.*                  # 上行入口令牌桶参数

```

`config/main/reason-main.env`（systemd EnvironmentFile）：

```

```

`config/sim/reason-barrier-sim.env`：

```

BARRIER_W02_SECRET=<32hex>
```

目录权限：`/opt/reason/config/` 700，yml/env 600，属主 ubuntu。

### 3.7 启动与健康检查

```bash
sudo systemctl enable --now reason-main reason-barrier-sim   # 必须在 MQ 三进程已启动之后

curl http://127.0.0.1:8200/api/actuator/health   # {"status":"UP"}
curl http://127.0.0.1:8300/sim/status            # 两台杆快照（sim 无 actuator，探业务端点）
```

> 平台不带 profile 启动会因缺数据源 fail-fast（T16 设计，预期行为）；systemd unit 已固定 `--spring.profiles.active=prod`，手工调试时勿省略。

### 3.8 防火墙

```bash

```

8300 / 9876 / 10911 / 8081 / 3306 / 6379 一律不放行（进程层已绑回环）。

## 4. 验收清单（升降杆形态）

| # | 验收 | 跑法（服务器上执行） |
|---|---|---|
| 1 | 平台健康 | `curl 127.0.0.1:8200/api/actuator/health` → UP |
| 2 | 模拟器在位 | `curl 127.0.0.1:8300/sim/status` → 2 台快照 |
| 3 | 心跳判活 | 登录取 token → `GET /api/device/record/list` → 2 台 online=true（10s 心跳） |
| 4 | 手动抬杆闭环 | `POST /api/device/command/open {"deviceNo":"BARRIER-E-01"}` → 3s 内台账 state 3→1，流水 PENDING→ARRIVED |
| 5 | 事件走 MQ | sim 日志无 reporter error；`sh bin/mqadmin consumerProgress -n 127.0.0.1:9876 -g platform-device-event` 见消费推进 |
| 6 | 自动对账 | 窗口外（默认 08:00-18:00 之外）等整分 → 日志 `自动对账发现偏差 ... 下发校正指令` |
| 7 | 重启恢复 | `sudo systemctl restart reason-main` → 健康恢复、心跳对账恢复、数据仍在 |
| 8 | 安全冒烟 | 配置文件无明文凭据（全 ENC）；白名单无幽灵路径（/druid、/sys/code 等不候选）；连续 5 次错误密码 → 账号锁定提示 |

登录接口：`POST /api/sys/login {"loginname":"adminManager","password":"<部署时种子密码>"}`，后续请求带 header `token`；**部署后立即改强密码**。

## 5. 日志与排障

- 平台：`sudo journalctl -u reason-main -f`；文件 `main/logs/`（info/warn/error 三桶，warn 桶含 ERROR）
- 模拟器：`sudo journalctl -u reason-barrier-sim -f`；文件 `sim/sim-logs/`
- MQ：`rockets/logs/*.out` 与 `~/logs/rocketmqlogs/`
- 跨进程串链路：sim 与平台日志均带 `[traceId]`，同一次抬杆可 grep 全链路（sim→broker→consumer→DB）
- 常见坑（本地已实证）：① 无 profile=数据源缺失 fail-fast，是预期不是故障；② sim 密钥文件缺行 fail-safe 不上报；③ broker 重启后 proxy 自动重连（~20s）；④ Redis 加载旧 dump 会致 seq 计数器回退，对账静默跳过（WARN `Duplicate entry`），排查=`barrier:cmd-seq:{deviceNo}` 对齐 `SELECT MAX(command_seq)`

## 6. 事件通道三态与回滚（批次3 落档）

| 形态 | sim 启动参数 | 平台侧 |
|---|---|---|
| mq（默认终态） | `--sim.event-channel=mq` | `reason.device.mq.enabled=true`（默认） |
| dual（对照） | `--sim.event-channel=dual` | 同上 |
| http（无 MQ 环境回滚） | `--sim.event-channel=http --sim.mq.enabled=false` | `reason.device.mq.enabled=false`（consumer 不启动） |

- `event-channel=mq` 与 `mq.enabled=false` 组合=启动 fail-fast（语义矛盾显式拒绝）
- 心跳恒 HTTP（判活不依赖 broker）；下行指令恒 HTTP（平台→sim :8300）
- MQ 故障语义：sim 侧失败缓冲队列（500）积压，恢复后补发；平台消费幂等吸收重复投递

## 7. 配置速查（prod 外部化常用键）

| 键 | 默认 | 说明 |
|---|---|---|
| reason.cors.allowed-origins | [] | 跨域白名单，空=仅同源（401 响应同规则回显） |
| reason.security.trusted-proxies | "" | 可信代理清单；空=忽略一切 XFF（防伪造） |
| reason.security.login-ip-max / login-ip-window-seconds | 20 / 600 | IP 维度失败闸 |
| sys_param.attempt_limit | 5 | 账号×IP 组合锁上限（08 迁移） |
| reason.audit.query-log-enabled | false | GET 查询是否写 sys_log |
| reason.device.traffic.* | 5rps/burst10、100rps/burst200 | 上行入口令牌桶（全局超限拒事件放行心跳） |
| reason.retention.* | 90 天 / 500 行每批 / 200 批上限 | job 203 每日 03:30 清理 |
| reason.barrier.* | 见 application.yml | 自动升降窗口/心跳超时/指令重试/保持期/告警去重 |

## 8. 备份与恢复

**备份（每日定时，脚本 `deploy/backup.sh`）**：

```bash
# 部署脚本与凭据（凭据写 env 文件 600，不写 crontab 明文）
sudo install -m 600 -o ubuntu deploy/backup.sh /opt/reason/config/backup.sh
sudo tee /opt/reason/config/backup.env >/dev/null <<'EOF'
MYSQL_PASSWORD=<数据库密码明文>
REDIS_PASSWORD=<redis 密码，如有>
EOF
sudo chmod 600 /opt/reason/config/backup.env

# crontab（ubuntu 用户）：每日 02:30
30 2 * * * . /opt/reason/config/backup.env && /opt/reason/config/backup.sh >> /var/log/reason-backup.log 2>&1
```

- 产物：`/opt/reason/backup/mysql/reason_faster_<ts>.sql.gz`（单事务一致性快照）+ `redis/dump_<ts>.rdb`（BGSAVE 后按 CONFIG 实际路径拷贝）；默认保留 7 天（`./backup.sh 30` 可调）
- **备份边界**：MySQL 全库 + Redis 覆盖业务数据；`.env`（设备密钥/解密口令）**不进自动备份**——另行离线留底（凭据独立于备份安全域）
- 演练记录：备份→恢复闭环已本地验证（mysqldump 全量→临时库导入→8 张关键表行数窗口核对全过）；脚本与证据 `scripts/verify/batch6/`

**恢复（危险操作：先停写入方）**：

```bash
# 1) 停平台（断写入，防恢复期双写污染）
sudo systemctl stop reason-main
# 2) MySQL 恢复
gunzip -c /opt/reason/backup/mysql/reason_faster_<ts>.sql.gz | mysql -u<user> -p reason_faster
# 3) Redis 恢复（可选：Redis 易失态均可重建——保持期回 DB 权威、在线判定有宽限；需要时按同时间点 RDB 恢复）
sudo systemctl stop redis-server
sudo cp /opt/reason/backup/redis/dump_<ts>.rdb /var/lib/redis/dump.rdb
sudo chown redis:redis /var/lib/redis/dump.rdb && sudo systemctl start redis-server
# 4) 起平台 + 校验
sudo systemctl start reason-main
curl -s http://127.0.0.1:8200/api/actuator/health          # UP
curl -s http://127.0.0.1:8200/api/sys/init | head -c 200   # code=0（真实 DB 往返）
```

- 校验基线：关键表行数与备份时点一致（device_record/流水/告警）+ 登录 + 一次抬杆闭环回归
- 恢复后核对：`db/` 已执行脚本集合与当前代码版本匹配（尤其含 09 毫秒化的版本）

## 9. 版本与回滚

**版本约定**：jar 产物 `reason-main-<主.次.修订>.jar`（当前 1.0.0）；每个发布版本在 `/opt/reason/releases/<version>/` 留档（jar + 对应增量 SQL 清单 + RELEASE-NOTES.md），`/opt/reason/main/` 为当前生效副本。

**发布流程**：构建机打包（main + sim）→ scp 到 `releases/<version>/` → `db/` 按文件名序执行增量 SQL → 替换 current → `systemctl restart` → 跑 §4 验收清单。

**回滚（纯代码版本，分钟级）**：

```bash
sudo systemctl stop reason-main
cp -r /opt/reason/releases/<上一版本>/reason-main-*.jar /opt/reason/main/
sudo systemctl start reason-main
```

- **边界（必须知道）**：增量 SQL **不自动回滚**——db/ 脚本是幂等前向迁移（如 09 毫秒化不可逆）；
  回滚代码前先查目标版本的 RELEASE-NOTES 是否标记
  "破坏性"：破坏性版本的回滚需自带反向 SQL（部署前从 db/ 评估并保留），纯代码版本直接换 jar 即可
- RELEASE-NOTES 建议字段：版本号 / 日期 / 增量 SQL 清单 / 是否破坏性 / 回滚步骤

## 10. 安全清单

- MySQL 建业务专用账号（仅 reason_faster 库、localhost）；Redis 启用 requirepass 且仅 127.0.0.1
- 平台 prod 凭据（DB/Redis）全 ENC；解密口令仅存 `reason-main.env`（600）
- 设备密钥：per-device 32hex，平台台账与 sim env 同值；仓库零明文
- /opt/reason/config/ 700、yml/env 600；jar/log 属主 ubuntu
- adminManager 首登改强密码；8300/中间件端口不对公网开放
- **公网口径**：8200 默认仅内网/SSH 隧道访问；确需公网暴露时必须经 nginx 反代 + TLS（HTTP 明文 token 不可公网直传），ufw 仅放行 443，并登记 `reason.cors.allowed-origins` 为真实前端源
- 维护窗口改配置：改 `config/main/**` 后 `systemctl restart reason-main` 生效
