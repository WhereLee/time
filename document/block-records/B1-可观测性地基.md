# 批次1：可观测性地基（块记录）

> 归属：升降杆样例终稿规格 §三 批次1（P4 sim 文件日志 + TraceId 贯穿 + logback 修复 + 结构化日志）
> 日期：2026-09-09 | 验证：单测 sim 21 + 平台 62 全绿；DoD 两条剧本实测通过

## 一、目的

阶段 3 量下回归必须有日志留证（阶段 2 F3 剧本被"sim 日志即焚"坑过——只能靠终端回滚找证据）；trace 不贯穿则事故定位停在通道级（红队 T17 原判："能定位到通道级+时间窗，到不了报文级"）。本批次把这两条能力补齐。

## 二、改动

### P4 sim 文件日志（reason-barrier-sim）
- 新建 `logback-spring.xml`：三桶（info/warn/error）文件 appender，按天+10MB 滚动 gz 归档，`maxHistory=30`
- 目录 `sim-logs/`，可用 `-DLOG_DIR` 覆盖（多进程模拟时隔离）
- pattern 含 `%X{traceId}`；`com.reason.barrier` 级别 DEBUG
- WARN 桶用 ThresholdFilter（吸收 WARN+ERROR）

### TraceId 全链路贯穿（D-E）
| 位置 | 改动 |
|---|---|
| sim `TraceIds`（新建） | 与平台 TraceIdFilter 同算法（16 字节 SecureRandom→32hex）同常量（HEADER=`X-Trace-Id`/MDC_KEY=`traceId`/MQ_PROPERTY=`traceId`）；`orGenerate(incoming)` 沿用或生成 |
| sim `EventReporter` 接口 | `report(...)` 增 traceId 参数——**显式传递而非 MDC 隐式捕获**：上报跨两级异步边界（动作线程→发送线程），显式可靠且可追溯 |
| sim `Barrier` | `execute(action,seq,traceId)`/`runAction(...,traceId)`（动作线程 MDC.put+finally remove）/`tamper(forced,traceId)`/`recover(traceId)`/`reportEvent(...,traceId)` |
| sim `DeviceService(Impl)` | open/close 增 traceId 透传；tamper/recover 用 `orGenerate(MDC.get())`（注入口已有则沿用） |
| sim `CommandController` | `/cmd`、`/cmd/query` 取 `X-Trace-Id` 头 → orGenerate → MDC.put/finally remove → 传 service |
| sim `SimController` | 注入口统一 `withTrace()` 包装（每次注入一个 traceId 置 MDC）——剧本取证依赖此 |
| sim `HttpEventReporter` | 发送线程 MDC.put（跨线程显式）+ HTTP header `X-Trace-Id` |
| sim `MqEventReporter` | PendingEvent 增 traceId 字段（随队列元素跨线程）+ drainLoop MDC.put + message property `traceId` |
| sim `HeartbeatReporter` | 每设备每轮生成 traceId（心跳是自发周期信号）+ MDC + header |
| 平台 `TraceIdFilter` | `generateTraceId()` 改 public（非 HTTP 入口也需生成链路号） |
| 平台 `DeviceCommandServiceImpl` | dispatch/queryState 下行携 `X-Trace-Id`（`currentTraceId()`：MDC 有则沿用，无则生成） |
| 平台 `BarrierAutoTask`/`BarrierMonitorTask` | run 包 MDC（本轮任务生成 traceId，doRun 承载原逻辑）——Quartz 线程无 HTTP 上下文，自动升降链路从此可追踪 |
| 平台 `DeviceEventMqConsumer` | handleOne 从 message property 取 traceId → MDC.put/finally remove（消费线程无请求上下文） |
| 契约 §3.1/§7.1 | 链路跟踪条目 + MQ property `traceId` 定稿 |

### 平台 logback 修复（T17）
- 三处 `maxHistory` 取消注释设 30（原注释掉=归档无限期堆积吃满磁盘）
- WARN 桶 LevelFilter(精确 WARN) → **ThresholdFilter(WARN)**：warn.log 现在吸收 WARN+ERROR（原分桶互斥使 warn.log 看不到 ERROR，排障丢上下文）；ERROR 桶保持纯 ERROR（便于告警渠道抓取）

### 结构化日志（报文级留痕）
- `DeviceEventController`：入口 `[事件入口] deviceNo/state/commandSeq/bootId/eventSeq` info 级（事件稀疏且每条有业务意义）；拒绝路径 warn 级（非法状态码/业务拒绝）
- `DeviceHeartbeatController`：入口 debug 级（心跳 10s/台高频，防刷屏；dev 下 com.reason=DEBUG 可见）；拒绝路径 warn 级
- traceId 由 pattern `%X{traceId}` 自动输出，无需入参

## 三、DoD 验收证据（实测）

### DoD-1：一次手动抬杆，同一 traceId 串起两侧全链路
traceId `b0aa90c39dd3a71d3c1a665167c023b1`（从平台响应头 `X-Trace-Id` 取得），grep 结果：

**平台 logs/info.log（12 条）**：手动指令下发(sendManual OPEN seq=23) → `[事件入口] state=3 commandSeq=23` → 台账更新(事件通道) → 手动保持期开启 → MQ 消费 eventSeq=1(序守卫拒=幂等吸收) → `[事件入口] state=1` → 台账更新 → MQ 消费 eventSeq=2 → **指令按 seq 精确销账(markArrivedBySeq)**

**sim sim-logs/info.log（8 条，来自文件非终端）**：Barrier 开始执行 OPEN seq=23 → 指令受理 → HTTP 上报成功 MOVING eventSeq=1 → MQ producer 就绪 → MQ 上报成功 MOVING → 动作完成 UP → MQ 上报成功 UP eventSeq=2 → HTTP 上报成功 UP

→ **跨进程同号串联**：从"管理端点击"到"台账销账"20 条日志一个 grep 拉全。

### DoD-2：事件通道中断剧本，报文级定位（红队 T17 原判被推翻）
注入 `blockEvents=true`（HTTP 事件通道独立断，MQ 正常）+ tamper E-01 DOWN，traceId `6d5eada87ba68c5c191c766f9ab861fa`：

| 侧 | 通道 | 日志证据 |
|---|---|---|
| sim | HTTP | WARN `[网络剧本] 事件上报被丢弃 deviceNo=BARRIER-E-01 state=DOWN` |
| sim | MQ | INFO `[MQ上报成功] deviceNo=BARRIER-E-01 state=DOWN` |
| 平台 | HTTP 事件入口 | **无记录**（DeviceEventController 零命中） |
| 平台 | MQ 消费 | INFO `[MQ事件消费] deviceNo=BARRIER-E-01 eventSeq=3` |

→ **凭一个 traceId 精确判定"这次上报 HTTP 通道被丢、MQ 通道送达"**——红队 T17 原结论"能定位到通道级+时间窗，到不了报文级"已被推翻（现在能答"哪几次上报到达、丢在哪一跳"）。

### logback 修复实证说明
maxHistory 与 WARN 桶 ThresholdFilter 为纯配置修复，语义确定（ThresholdFilter(WARN) 必然吸收 ERROR）。本次运行窗口 sim/平台均未产生 ERROR 级日志（sim warn.log 12 条全 WARN、平台 warn.log 65 条全 WARN），故该修复**未被实际数据触发验证**——如实记录，不伪造证据。

## 五、遗留与边界

1. **心跳 traceId 每轮新生成**：心跳是自发周期信号无上游链路，每设备每轮一个号（用于"某台设备某一轮心跳"两侧对照），不与会话级链路关联——符合语义，非缺陷。
2. **Quartz 任务轮次一个 traceId**：一轮任务内多设备共用同号（日志靠 deviceNo/seq 字段区分）；未做"每设备每指令独立号"（过度，且下发时 dispatch 已带同号可在 sim 侧延续）。
3. **WARN 桶吸收 ERROR 未被数据实证**（见 §三说明），配置正确性由 logback 语义保证。
4. sim 日志目录 `sim-logs/` 需加入 .gitignore（避免日志入库）。
