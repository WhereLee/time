# 阶段1：调度健壮性与双实例集群实证（块记录）

> 归属：升降杆样例红队路线 §6 阶段1（T11/T12/T13/T15 + 双实例实证）
> 日期：2026-09-08 | 验证：单测平台 54 + sim 14 全绿；单机双进程实测

## 一、目的与范围

把"调度"从**配置了集群**变成**跑过互斥、失败可诊**：补 sim 心跳并行化前置（P5/T11）、任务失败根因保留（1a/T12）、分页与 Redis N+1（1a/T15）、任务防重叠与双实例启动竞态（1b/T13）、双实例 Quartz 集群互斥与故障接管实证（1c）。

## 二、改动

### P5 心跳并行化（reason-barrier-sim）
- HeartbeatReporter：单线程逐台串行 → **每台设备独立 scheduleAtFixedRate 任务**（共享有界线程池 heartbeat-threads 默认 8，谁慢只丢自己的轮）；上电自述并行一轮
- HTTP 客户端：SimpleClientHttpRequestFactory（每次新建 TCP）→ **JDK HttpClient（JdkClientHttpRequestFactory）连接复用**；事件上报同步替换（单发送线程保序不变——乱序会被平台序守卫拒）
- 超时参数化：`sim.connect-timeout-seconds`（默认 2）/`sim.read-timeout-seconds`（默认 5，原心跳 2s/事件 3s 硬编码）
- 注入器扩展：`heartbeatDelayMillis`（POST /sim/network 运行时注入，P7 时序剧本：人为延迟只拖本设备轮次）

### 1a T12 任务失败根因保留（reason-main）
- ScheduleJob：反射异常必包 InvocationTargetException——catch 取**最内层 cause** 落 schedule_job_log.log_error；error.log 带 jobId+jobBean+根因全堆栈（不再只记一行外层 toString）
- 不重抛 JobExecutionException：分钟级任务内部幂等自带自愈，misfire 重触发放大告警面；失败双落点可见交人工

### 1a T15 管理端健壮性
- 新增 `PageParams`（common.utils）：page 下限 1、limit 夹 [1,200]；非数字/溢出按默认钳制——**非法输入不再 500**（低权用户垃圾参数 DoS 面关闭）
- 三处替换：DeviceRecord/DeviceAlarm/DeviceCommandLog queryPage
- DeviceRecord 列表在线状态：每行 hasKey → **pipeline 一次往返**（RedisCallback exists 批量）

### 1b T13 调度并发与启动竞态
- ScheduleJob 类加 `@DisallowConcurrentExecution`（防单轮超周期重叠：双实例各取各 seq 双发物理动作）
- ScheduleJobServiceImpl.init()：create 撞 `ObjectAlreadyExistsException`（ScheduleUtils 包成 RRException，按 cause 链识别）→ **冲突即 update 幂等**——双节点同启第二节点不再 Bean 初始化失败

### 1c 双实例实证配套
- logback：`LOG_FILE_PATH=${LOG_DIR:-logs}` 环境变量可覆盖（第二实例 -DLOG_DIR=logs-node2 日志隔离）

### 实测暴露补漏（非计划内，实证逼出）
- **心跳恢复未关闭 OFFLINE 告警**：主节点被杀期间平台自收不到心跳 → 次节点正确 raise OFFLINE；主节点恢复后心跳到达，但旧代码无恢复反向标记 → 离线告警滞留未处理列表
- 修复：`markOnlineRecovered(deviceNo)`（DeviceAlarmService）——只关 OFFLINE（心跳到达 = 离线判定反转的唯一权威）；MOVING_STUCK/AUTO_CORRECT_FAILED 仍需事件级证据（动作到位/校正闭环），仍由 markRecovered 在事件路径关
- DeviceMonitorServiceImpl.heartbeat 第 4 步调用
- 单测补钉：DeviceMonitorServiceImplTest 5 用例（该路径此前零单测）

## 三、验证证据（实测记录）

### P5 心跳并行（sim 日志实录）
- 注入 `heartbeatDelayMillis=6000` 30s：两台设备每轮准点触发（+11s/+10s/+10s），零跳轮；全程平台在线稳定

## 四、遗留与已知边界

1. type5 熔断告警在 alarmDedupSeconds=300s 去重窗口内的**周期提醒**属设计语义（"还在坏的周期性提醒"）；W-02 历史剧本超限流水（seq14 RETRY_EXCEEDED，0.3 剧本残留）使熔断窗口持续命中——夜间无应然变化不产生 ARRIVED，熔断持续至下一个应然变化（08:00 放行窗口动作闭环后窗口滚动自愈）。告警疲劳治理（风暴限速）在阶段 4 T10。
2. markOnlineRecovered 每次心跳一次 UPDATE（device_no 无索引，小表可接受）——阶段 3 批量设备时需 pipeline/标记门控优化（代码已注明）。
3. scanOffline 逐个 EXISTS（注释已注：生产批量走 pipeline）——阶段 3。
4. 双实例实证用本地双进程；NTP/网络分区/时钟漂移类留阶段 3 混沌剧本。
5. 实证后已回退单实例常态运行（8200 主节点 + 8300 sim）。
