# 升降杆完全闭环（块4-5）：监控、自动升降与全边界落地

## 目标

把升降杆样例从"手动指令闭环"（块1-3：台账/指令/事件）推进到**完全闭环**——此前讨论的 14 个现实边界 + 五大机制全部落成可运行、可验证的代码，而不是停在注释里的"后续块"。

## 架构总览

```
管理端(人)                     平台 reason-main(8200)                模拟器 reason-barrier-sim(8300)
   │  手动升/降 @RepeatGuard        │                                      │
   ├──────────────────────────────>│  DeviceCommandService                │
   │  @ManualHold 保持期(Redis)     │   seq=Redis INCR → 流水PENDING        │
   │                               │────── POST /cmd {deviceNo,action,seq}─>│ Barrier 状态机裁决
   │                               │                                      │  (幂等/防砸/故障)
   │                               │<──── POST /device/event (状态事件) ────│ 动作异步执行
   │                               │  DeviceEventService:                 │
   │                               │   台账更新→流水ARRIVED→故障告警        │
   │                               │<──── POST /device/heartbeat(10s) ────│ HeartbeatReporter
   │                               │  DeviceMonitorService:               │  (上电自述+周期)
   │                               │   对账校正→Redis online TTL 30s      │
   │                               │                                      │ /sim/* 物理世界注入口
   │  Quartz barrierAutoTask(1min) │  应然(TimeRule) vs 实然(台账)          │ (fault/tamper/vehicle)
   │  Quartz barrierMonitorTask(30s)│ 超时重试(同seq)→超限告警 / 离线扫描     │
```

三本账：**台账**（设备最近说自己是什么，只信事件/心跳）、**指令流水**（平台发过什么、等到没等到）、**告警**（异常显式化交人工）。sys_log 另记管理端操作审计。

## Redis 使用清单（每个 key 的不可替代理由）

| key | 机制 | 为什么非 Redis 不可 |
|-----|------|-------------------|
| `barrier:online:{no}` TTL 30s | 心跳续命，过期即离线 | 把过期时间当业务逻辑，免定时扫库比对时间戳 |
| `barrier:manual-hold:{no}` TTL 30min | 手动保持期，自动规则让位 | 自动到期的临时状态，DB 表做需要清理任务 |
| `barrier:alarm-dedup:{no}:{type}` SETNX TTL | 告警去重窗口 | 原子占位免查-插竞态，持续异常不刷屏 |
| `barrier:cmd-seq:{no}` INCR | 指令幂等序号 | 原子递增跨实例一致，DB MAX+1 有并发竞态 |
| `rg:{userId}:{method}` SETNX TTL | @RepeatGuard 防连点 | 同上（块3已有） |

## 自定义注解 + AOP（案例技术要素）

- `@RepeatGuard` + RepeatGuardAspect：防连点（SETNX 原子占位）
- `@ManualHold` + ManualHoldAspect：手动保持期（注解声明"这是手动通道"，切面执行"开保持期"）
- `@SysLog` + SysLogAspect（框架）：管理端操作审计，成功失败都留痕

## 三轮审查循环记录（CodeReview 子 agent）

**第 1 轮**（1 P1 + 3 P2，全修复）：
- P1 流水状态推进无 CAS 守卫：monitor（Quartz 线程）与事件（HTTP 线程）竞态可把 ARRIVED 覆盖成 RETRY_EXCEEDED → 全部跃迁改 `casStatus(from=PENDING)`，markRetryExceeded 返回 boolean，未命中不告警
- P2 心跳把指令驱动的 MOVING 误报漂移 → 对账只对稳定态（UP/DOWN/FAULT）
- P2 sendByRule 的 nextSeq/recordPending 在 try 外，单台异常中断整轮 → autoTask per-device try/catch（reconcileOne 抽方法）
- P2 ManualHoldAspect 未判空 LoginUserHolder → 判空降级不阻断业务

**第 2 轮**（核查 5 项修复全对 + 1 P1 + 4 P2，全修复）：
- P1 首次心跳必误报 STATE_MISMATCH（建档 0 vs 自述 2）→ 首次接入豁免：只校正不告警
- P2 陈旧心跳可回退台账（两通道 last-writer-wins）→ 时序让路守卫：台账 grace 窗口(3s)内刚被事件更新则本轮跳过（真漂移不自愈下轮必抓，时序差自愈让路免误报）
- P2 Redis seq 丢失后 INCR 从头撞唯一索引 → @PostConstruct seedSeqFromDb 播种 DB MAX
- P2 告警 SETNX 占位先于落库，save 失败吞掉整窗口告警 → 失败 delete 占位再抛
- P2 token String.equals 短路时序侧信道 + sim 注入口监听 0.0.0.0 → DeviceChannelProperties.matches 常量时间比较（MessageDigest.isEqual）收口 + sim server.address=127.0.0.1

**第 3 轮**（核查 5 项修复全对 + 0 P0/P1 + 4 P2，全修复）：
- 注释同步：DeviceMonitorService 接口/impl 类注释补让路+首次豁免分支语义
- DeviceCommandLogEntity @Schema 补状态 4-执行失败
- seedSeqFromDb 包 try-catch：播种是尽力恢复不是启动强依赖
- 播种边界注明：仅处理 key 缺失（全量丢失），不处理 key 落后（旧快照部分回退）

**过程中自发现自修**（验证阶段）：monitor 重试前未看台账实然——事件丢失但心跳已把台账校正到位时盲目重试+误告警 → 重试前先对账销账（台账已达目标态直接 markArrived）。

## 关键验证证据（本地端到端日志摘录）

- 自动升降：`自动对账发现偏差 deviceNo=BARRIER-W-02 实然=2 应然=1 -> 下发校正指令 OPEN` → `指令到位闭环 seq=1`
- Quartz 集群恢复：`ClusterManager: detected 1 failed or restarted instances` + `Freed 1 acquired trigger(s)` + misfire 处理
- 上电自述对账：`心跳对账发现状态漂移 台账=1 设备自述=2 -> 以设备为准校正` + STATE_MISMATCH 告警
- 事件丢失销账：`超时指令经台账对账确认已到位，销账 seq=3（到位事件丢失，心跳对账兜底）`
- 超时重试→超限：`指令超时重试 seq=2 已重试=0/1` → `告警 type=指令重试超限 停止重试转人工`
- 离线判定：停 sim 35s → `online=False` + OFFLINE 告警 + Redis online key 自然过期（零扫库）
- 防砸/卡杆/故障拒令/复位/外力改态：sim 注入口全链路验证，SIM 与 DB 状态最终一致
- 单测：平台 35 绿（含 BarrierTimeRuleTest 3）+ 模拟器 10 绿（BarrierTest 全边界）
