## 三、F3 端到端剧本证据（本机真实 broker，2026-09-08 22:38-22:50）

### 剧本 1：双写正常链路
- 22:45:53 手动 OPEN E-01（seq=21）→ sim 执行 MOVING→UP
- sim 日志：`[MQ上报成功] eventSeq=1(MOVING)` + `eventSeq=2(UP)`（HTTP 同步成功）
- 平台日志：22:45:55/56 `[MQ事件消费] eventSeq=1/2`——**HTTP+MQ 双达**
- DB：流水 seq=21 OPEN status=1（ARRIVED）**唯一**（HTTP 先到销账，MQ 后到被业务幂等吸收）；台账 state=1

### 剧本 2：broker 故障（D3 故障域隔离 + sim 缓冲不丢）
- 22:48:36 杀 broker → tamper E-01 UP（eventSeq=4）
- HTTP 通道：22:48:41.957 上报成功（台账即时更新 state=1/seq=4——**双写期 HTTP 兜底**）
- MQ 通道：退避重试 5 次（1s/2s/3s/4s/5s）→ 22:49:09 `[MQ上报转入待恢复] 事件持留队首按 5s 节拍等待`（**队首持留不丢不乱序**）
- 22:49:38 broker 重启 → **22:50:04 `[MQ上报成功] eventSeq=4`**（按序补发）
- 平台：22:50:04.498 `事件被序拒绝(同代旧序/重放,幂等丢弃)`——MQ 补发消息被序守卫吸收（HTTP 已处理），**双写期对照痕迹**
- 期间 consumer 连接断→5s 节拍自动重建（22:48:41/49、22:50:01 三次 `consumer 已就绪`）——**平台不因 broker 故障炸**
- **设备在线全程 True**（心跳 HTTP 通道不受 broker 故障影响——D3 收益实证）

### 剧本 3：平台重启窗口（MQ 独有价值——HTTP 做不到的）
- 22:46:49 杀平台 → sim tamper E-01 DOWN（eventSeq=3）
- HTTP：重试 3 次耗尽丢弃（22:47:00 `[上报失败-重试耗尽]`——平台死，事件 HTTP 通道永久丢失）
- MQ：22:46:54.230 `[MQ上报成功] eventSeq=3`（**消息持久化在 broker**）
- 22:47:40 平台重启 → 22:47:47.846 `[MQ事件消费] eventSeq=3` → 台账 state=2（DOWN）+ device_last_event_seq=3
- **结论：平台死 73s 期间 HTTP 丢失的事件，MQ 通道零丢失补账**——规格验收"平台重启 60s 期间设备上报事件 → 重启后全部消费、流水终态一致"达成

## 四、CI 策略结论（规格 F2 三选一）

选**策略②**：@Tag("mq") IT 独立 job（Testcontainers rocketmq 容器，broker --enable-proxy 内嵌 gRPC 免第三容器）。本地无 Docker → IT 仅 CI 跑（*IT 命名天然隔离 surefire）。**mq-it job 首跑结果见提交后 CI**；若 >2 次红按规格显式降级（策略③：本地手动验证+CI 只编译单测），降级证据补录本节。

## 五、遗留与边界

1. **client-java 5.2.2 vs 规格 5.3.x**：外部 agent 选 5.2.2（注"版本线独立于服务端"）——实测连 broker 5.3.1 proxy 兼容（F3 剧本全过）。若 5.3.x 已发布可升级，非阻塞。
2. **broker 注册地址局域网 IP**：换网络后失效，建议 broker 启动加 `brokerIP1=127.0.0.1`（MQ-ENV-NOTES §3-4）。
3. **双写期终态**：HTTP 通道未退役（D6，退役判定在阶段 3 量下回归通过后）。
4. **消费组 retryMaxTimes**：未显式配置（broker 默认）——毒消息路径由消费端 ack 丢弃控制，不依赖重投上限；瞬时异常重投次数按默认，阶段 3 上量时按需调。
5. **JSON 库不对称**：main 消费器 fastjson2 / sim 发送器 Jackson——各自沿用所在模块既有依赖，无功能问题。
6. **MQ 消费组多实例负载均衡**：不在本阶段（单队列保序前提），阶段 3 扩队列+每设备 message group 时再议。
