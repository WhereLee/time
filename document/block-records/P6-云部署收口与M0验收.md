## 二、关键决策与坑（P6 实录）

1. **壳子数据源键结构**：DynamicDataSourceConfig `@ConfigurationProperties(prefix="spring.datasource.druid")` → 外部覆盖必须写 `spring.datasource.druid.url/username/password`（写 `spring.datasource.url` 无效——首轮失败根因）
2. **MySQL8 caching_sha2_password**：业务账号 TCP 首连报 `Public Key Retrieval is not allowed` → URL 加 `allowPublicKeyRetrieval=true`（本地 root 用 socket/缓存无此问题，服务器新账号必踩）
3. **Jasypt CLI 生成密文**：`java -cp jasypt.jar:commons-cli.jar:commons-codec.jar org.jasypt.intf.cli.JasyptPBEStringEncryptionCLI`（jasypt 1.9.3 瘦 jar 需 commons 依赖，缺则静默失败输出空 → ENC() 空密文）；输出段取 `----OUTPUT` 后首个非空行，自行包 `ENC(...)`；算法必须与 starter 默认一致 `PBEWITHHMACSHA512ANDAES_256` + RandomIvGenerator
4. **YAML 顶层键重复 = 解析失败**：python 字符串插入把第二个 `spring:` 拼进已有文件 → Application run failed 循环重启（`systemctl is-active` 仍显示 active 的假象期间 journal 每 6s 一次失败）。整文件重写而非补丁式注入
5. **systemd Restart=on-failure**：启动失败进程被反复拉起（6s 周期），journalctl 按时间窗过滤才能看到当前失败根因（否则看到的是旧进程刷屏）
6. **验证码**：SysLoginForm 的 captcha 字段已注释（免验证码登录）——登录只需 loginname+password
7. **表列名实证**：时间列 `session_entry_time`（非 entry_time）、金额列 `amount_fen`（非 order_amount_fen）——验收脚本列名错误导致"计费 0 分"假失败；FeeCalculator 0 秒防御反而被意外实证（duration=0 → 0 分）
8. **验收断言基于流程推导**：完整流程订单数 2（A-001 出场 + A-003 计费），首版断言 3 错误
9. **PowerShell 内联命令引号/多文件 scp/`$(...)` 本地解析**全部炸过一遍 → 服务器操作一律本地写脚本 → scp → `bash /tmp/xxx.sh` 执行（与《服务器连接文档》协作规范一致）
