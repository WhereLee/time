## 二、关键设计决策（块内定稿）

1. **跨方凭证化边界（岔路 C 落地）**：parking/charging 同进程但互不直连对方表——charging 暴露能力接口（OngoingParkSession 只读视图、BenefitService check/redeem），parking 出场事务内调 redeem（REQUIRED 同事务原子核销+结算）；对账 job 是唯一"对账例外"可直读双方表（类注释声明合法化）
2. **双判官并发模型**：会话终态化条件更新（第一判官）+ 权益核销条件更新 `WHERE benefit_no=? AND state=0 AND anchor_session_id=?`（第二判官）；双花败方（redeem false）→ 修正订单 discount=0/benefit_no 清空 + warn，不挡出场
3. **减免算法**：应收 = 计费原公式不动（按小时向上取整）；减免 = `floor(free_seconds×unitPrice/3600)` 且 min(应收)；amount_fen 保持应收原义 + discount_fen/benefit_no 快照，实付可推导不入库
4. **settle 共享结算链路**：finish（→FINISHED）与 timeoutFinish（→TIMEOUT_FINISHED 0电0元）共用私有 settle：判官终态化→读启用费率→订单快照→电量>0 签权益→桩释放（0 行回滚暴露）
5. **充电计费口径**：电量 Wh 整数、两段单价 fen/kWh、段金额各自 `(Wh×单价+500)/1000` 四舍五入到分、总额=电费+服务费（快照恒等）；0 Wh 不发权益（堵免费薅权益）
6. **桩台账规则**：绑定位须存在/未停用/无进行中停车会话（装桩施工语义）；充电中禁编辑；状态只收 0/2（1 由会话事务管理不接受手动置位）；编号唯一预查重+DB 兜底

**验收脚本三版迭代教训（本块实景，防再踩）：**
1. yml token 提取：配置为 `access-token: xxx` 无引号，`awk -F'"'` 取空 → 设备接口全 401；改 `sed -E 's/.*access-token:[[:space:]]*//'`
2. 响应 data 形态不可猜：`"data":123` 裸数字与 `"data":{"orderId":123}` 嵌套并存 → pick() 通用函数兼容
3. **按小时向上取整的造数边界**：回拨 7200s 若脚本耗时 >0 即跨 2h→3h 边界收 600 分；时长须落在取整区间中部（V2 用 6600s 稳收 400、V3 用 1800s 稳收 200）
4. 权益有效窗 24h：过期造数只回拨 1h 不够，须回拨 >24h（90000s）
5. 环境车位只有 B-001~003（无 A 区）：脚本拍脑袋的 A-003 不存在，造数前先查表
6. job cron 被验收临时统一每分钟后必须恢复默认（CASE WHEN 按 job_bean 回写），否则污染调度参数
7. 验收脚本自身中文/引号笔误两处（eecho、尾部多引号）→ 上传后先 `bash -n` 再跑
