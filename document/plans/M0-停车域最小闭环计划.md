# M0 计划：停车域最小闭环（设备控制型智慧停车位）

> 状态：设计讨论中（块循环第 1 步，待 3 个确认点拍板后进入 P1）
> 关联：总体计划 v2 M0 行；本文档为 M0 执行计划，落地结果以 block-records 记录

## 1. 目标与验收标准（M0 done 定义）

**目标**：跑通「设备上报 → 会话状态机 → 计费 → 订单」最小业务闭环（业务进程 + device 进程双进程），并发正确性三件套（状态机守卫/条件更新/事务原子）在真实代码中成立。

验收：
1. 管理后台可建档车位（RBAC 权限内，权限串注册 sys_menu）
2. 入场/出场/取消全链路 HTTP 可用（device-sim 触发 + 手动接口兜底）
3. **同一车位并发入场仅一个成功**（并发用例可复现）
4. 非法状态迁移被拒绝（已结束会话不可取消、已取消不可结算等）
5. 全部单测绿（存量 32 + 业务新增）+ CI 绿
6. device-sim 独立进程可启停，收到开闸/落锁指令可见（日志）
7. （部署前置满足后）云服务器双进程部署跑通——部署前必须完成设备接口最小鉴权（静态 token），公网可达前不做即缺口

## 2. 范围边界

**做**：车位建档管理；停车会话（入场/出场/取消）；按时长计费（单规则）；订单生成；会话/订单查询（分页）；车位状态联动；device-sim 最小化（事件上报 + 指令回显）；设备接口最小鉴权（部署前置）。

**不做（后续块）**：支付/对账（结算域）、RocketMQ、调度治理、设备心跳/在线状态（M2）、充电域与优惠（M1）、计费规则引擎多策略（M2）、预约/固定车位、报表、真实车牌识别。

## 4. 领域对象草案（字段级在小步 P1 讨论定稿）

- `park_space` 车位：id、编号(唯一)、区域、状态(空闲/占用/禁用)、创建信息（复用审计字段风格）
- `park_session` 停车会话：id、车位 id、车牌号、入场时间、出场时间、状态(进行中/已结束/已取消)、取消原因、创建人
  - 并发唯一性**不依赖索引**（条件更新语义），应用层查重兜底
- `fee_rule` 计费规则：id、名称、单价、是否启用——M0 单规则（默认规则），多策略 M2
- `park_order` 订单：id、会话 id(唯一)、车牌、车位、入场/出场时间、时长分钟、金额、状态(已生成)、创建时间

状态机（会话）：`进行中 → 已结束 | 已取消`；已结束/已取消为终态不可迁移；取消仅进行中可发起（车位释放）。

## 5. 接口面草案

管理端（权限串前缀 `park:space:*`、`park:session:*`、`park:order:*`，注册 sys_menu）：
- 车位 CRUD + 列表分页；会话/订单列表分页查询

设备/开放端（部署前加静态 token 头校验）：
- `POST /api/parking/device/entry`（车位编号 + 车牌 → 会话创建）
- `POST /api/parking/device/exit`（会话 → 结算订单）
- `POST /api/parking/device/cancel`（误入场撤销）

device-sim 进程：手动/脚本触发上述调用 + 模拟收到控制指令打日志（开闸/落锁）。
