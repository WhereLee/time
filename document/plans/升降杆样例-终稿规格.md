# 升降杆样例——终稿规格（最终形态与执行序）

> 性质：**执行终稿**——定义样例最终做成什么样子 + 剩余工作分批序 + 每批可判定验收。主 agent 自执行用，所有决策已定死。
> 基线：阶段 0（协议 v2/HMAC/监控自治/告警闭环/Redis 容灾）+ 阶段 1（调度健壮性/双实例实证）+ 阶段 2（MQ 事件双写通道）已完成，CI 绿。
> 出处：红队路线 §6 阶段 3/4 + 横切治理 + 逻辑机制清单 P1-P8 + 附录 A 三档取舍
> 日期：2026-09-09

## 一、终态全貌（最终做成什么样子）

### 1.1 业务形态
- **50 台升降杆**（配置驱动批量注册，非硬编 2 台），每台独立心跳/事件/指令/密钥
- 时间规则自动升降（08:00-18:00 放行）+ 手动接管（保持期让位）+ 故障熔断 + MOVING 巡检——全部在 50 台量级下不塌
- 告警完整闭环：产生→确认→恢复自动关，**风暴限速**（批量离线不刷屏）

### 1.2 技术形态
| 通道 | 终态 | 说明 |
|---|---|---|
| 事件上行 | **MQ 单通道为默认**（`sim.event-channel=mq`） | HTTP/dual 模式保留为配置开关（降级/对照能力，零代码切换）；退役判定见批次 3 |
| 心跳上行 | HTTP（D3 定稿不变） | 判活要有界时延，不依赖 broker；broker 故障时心跳+自述对账仍活 |
| 下行指令 | HTTP（含 QUERY_STATE） | 同步请求应答语义，无异步化需求 |
| 调度 | Quartz 集群（双实例已实证） | 50 台量级下任务扫描不超周期 |
| 可观测 | TraceId 全链路贯穿 + sim 文件日志 + 任务看护 + 第 0 档指标 | 事故可定位到**报文级**（哪次上报到达、丢在哪一跳） |
| 安全 | per-device HMAC（已）+ 配置安全收敛 + 认证前置 + 上行入口限流 | 云部署形态下无上线阻断项 |

### 1.3 证据形态（终态交付物）
- 量下回归剧本报告：50 台 × 坏网络注入 × 断言集全过
- 事故定位演示：重演"事件通道中断 5 分钟"→ trace 贯穿定位到分段（sim→broker / broker→consumer）
- 每批次 block-records 记录 + 红队文档落地标注

## 二、关键终态决策（定死，执行时不再讨论）

| # | 决策 | 定稿 | 理由 |
|---|---|---|---|
| D-A | HTTP 事件通道是否退役 | **不物理退役，改配置开关**：`sim.event-channel=mq\|http\|dual`（默认 mq）；平台侧 HTTP 事件入口保留但默认不被调用 | 阶段 2 剧本 2 实证双通道互补价值（broker 故障 HTTP 兜底）；物理删除=失去降级能力；配置切换零代码成本 |
| D-B | 多站点 | **不做** | 附录 A "批量/多站点"中多站点属停车语境（车场），升降杆样例无站点业务语义，硬编=伪需求 |
| D-C | 设备规模 N | **50 台**（红队文档阶段 3 既定） | 5rps 心跳量级压不出 DB 池争抢；50 台 × 10s = 5rps 心跳 + 事件洪峰足以暴露 CAS/去重/扫描问题；不上 100+（边际收益低，配置/密钥管理成本陡增） |
| D-D | 指标方案 | **第 0 档**：actuator health/info（已有）+ 新增业务指标端点 `/api/device/metrics`（DB/Redis 派生：PENDING 积压/在线率/任务最后执行时间/告警未处理数）；**不引 Prometheus/Micrometer 注册表** | 记忆既定第 0 档原则；单体样例引重量级链路框架=装饰 |
| D-E | TraceId 贯穿方案 | sim 生成 traceId（每事件/每指令周期一个）→ HTTP header `X-Trace-Id` / MQ message property → 平台 TraceIdFilter 已吃入站头（复用）→ MDC 落日志；**MQ 消费侧从 property 取 traceId 塞 MDC** | 平台侧基建已有（维度三交付），只补 sim 侧生成 + MQ property 承载 |
| D-F | 告警风暴限速 | Redis 滑动窗口计数（per-type 全局，超阈值只记日志不落库）+ 批量 OFFLINE 合并告警（一条"批量离线 N 台"替代 N 条） | T10 增强既定方向；50 台同时离线=50 条告警刷屏是真实事故形态 |
| D-G | 表保留策略 | 新增 Quartz 清理 job（每日）：device_alarm/device_command_log/sys_log 保留 90 天，物理删除超期行（分批 LIMIT 防长事务） | 长期运行表无限膨胀是运维债；90 天足够审计回溯 |
| D-H | 秒级时间戳 | **改毫秒**（device_record/command_log/alarm 的 createtime/updatetime 列改 bigint 毫秒 + 代码 /1000 处全改）；reconcileGraceSeconds 语义不变 | 秒级与 grace=3s 同量级 ±1s 抖动是真实隐患；改毫秒一次到位优于放大窗口 |

> D-H 是**破坏性变更**（DB 列语义 + 全代码时间戳），单独成批次末尾执行（前四批不碰时间戳，避免与量下回归断言耦合）。

## 三、执行序（五批次，按依赖+价值排）

### 批次 1：可观测性地基（P4 + TraceId + logback + 结构化日志）——✅ **已完成（2026-09-09）**

> 落地证据见 document/block-records/B1-可观测性地基.md：DoD-1（一次手动抬杆 traceId `b0aa90c3...` 串起两侧 20 条日志，sim 日志来自 sim-logs/ 文件）+ DoD-2（blockEvents 注入后凭 traceId `6d5eada8...` 定位"HTTP 通道丢/MQ 通道达"报文级）均实测通过；单测 sim 21 + 平台 62 全绿。logback 修复为纯配置变更，本运行窗口无 ERROR 产生故未被数据触发（已如实记录）。

**为什么最先**：阶段 3 量下回归剧本需要 sim 日志留证据（阶段 2 F3 剧本已被"sim 日志即焚"坑过一次——只能靠终端回滚找证据）；trace 不贯穿则事故定位停在通道级。

| 项 | 内容 | 验收 |
|---|---|---|
| P4 sim 文件日志 | sim 加 logback-spring.xml（文件 appender + 滚动 + maxHistory），日志目录 `sim-logs/` | sim 重启后历史日志可查；F3 类剧本证据从文件取 |
| TraceId 贯穿 | sim 每事件/指令周期生成 traceId（UUID 短码）→ HTTP header + MQ property；平台 MQ 消费侧从 property 塞 MDC | 一次手动抬杆：sim 日志→平台 HTTP/MQ 消费日志→流水/告警，同一 traceId 可串起 |
| logback 修复 | 平台 maxHistory 取消注释（30 天）+ ERROR 桶加 ThresholdFilter 吸收 WARN | warn.log 不再看不到 ERROR；归档不无限堆积 |
| 结构化日志 | 事件/心跳/指令入口日志字段化（deviceNo/eventSeq/seq/traceId/state） | grep deviceNo 可拉出该设备全链路 |

**批次 DoD**：重演"事件通道中断 5 分钟"剧本 → 凭 traceId+文件日志定位到**报文级**（哪几次上报到达、丢在 sim 侧还是平台侧）。

### 批次 4：告警增强 + 任务看护 + 指标（阶段 4 剩余）

## 五、明确不做（防膨胀红线）

- ❌ 多站点/车场语境（D-B）
- ❌ 设备数 >50（D-C，边际收益低）
- ❌ Prometheus/Grafana/SkyWalking 等重量级观测栈（D-D 第 0 档）
- ❌ 断电保位变体、运动中防砸重仿真（附录 A "砍"档，违背控度红线）
- ❌ 设备注册制动态令牌（D2 既定：留主线立项，与多租户 B 同批）
- ❌ TLS 启用（物理同机无暴露面；应用层签名不因同机豁免——已做）
- ❌ 多租户/账务（样例边界外，主线立项块）
- ❌ L4 调度平台（XXL-Job 等，L3 止盈点已过）
