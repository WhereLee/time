# M1 计划：充电域（charging）与跨方优惠联动

## 1. 目标与验收标准（M1 done 定义）

**目标**：跑通「车停带桩车位 → 充电会话（电量计费：电费+服务费两段费率）→ 充电订单 → 充电方签发免停权益 → 出场结算时停车方凭证化核销减免」跨方联动闭环；Quartz 从空转升级为有业务负载（权益过期/会话超时巡检/跨方对账）；设备模拟扩展充电桩。

验收：
1. 充电闭环 HTTP 可用（桩设备上报开始/结束 → 会话 → 两段费率订单，金额快照正确）
2. 权益全生命周期成立：充电完成签发 → 出场核销减免 → 有效期过期自动作废（调度 job 实证）
3. **同一权益并发核销仅一次成功**（核销判官，复现用例）
4. 停车减免金额正确：减免与取整先后的边界用例（跨小时/超免停时长/零时长）全绿
5. 管理端权限隔离：充电菜单（3xx）与停车菜单（2xx）分角色可查，越权拒绝
6. 全部单测绿（存量 83 + 新增）+ CI 绿（04 脚本挂载容器）
7. 云服务器部署后 M1 验收清单实跑全过（含调度 job 日志实证 + 重启恢复）

## 2. 范围边界

**做**：充电桩台账（绑车位，不重建空间模型）；充电会话（开始/结束/取消 + 判官）；电量计费（固定电费单价 + 服务费，两段快照）；免停权益（凭证化签发/核销/过期状态机）；停车结算减免改造（FeeCalculator 扩展 + park_order 快照扩展 + 核销与出场结算双判官同事务）；Quartz 业务 job（权益过期/充电会话超时巡检/长期占用巡检/跨方对账）；device-sim 充电桩扩展（事件 + 总电量上报）；充电管理端最小面（桩/会话/订单/权益查询）；授权脚本 04 固化。

**不做（后续块）**：支付语义（订单无支付状态，M0 同构）；峰谷分时电价（费率引擎 M2）；遥测实时存储与心跳/在线状态（M2 IoT 线）；充电桩独立进程/独立库（演进拆分条件未到，见决策记录）；优惠叠加/多规则（先单张核销）；停车支付补全。

## 3. 模型与决策记录（2026-09-05 已确认）

| 决策 | 内容 | 理由链 |
|---|---|---|
| 跨方形态 = 同进程 + **凭证化协议边界**（岔路 C） | 不拆 charging 进程；parking/charging 各自自治，跨域不共享表直连：charging 签发权益（凭证实体：幂等键/有效期/状态机），parking 出场**凭凭证核销**（条件更新判官防双花），按"不可信对方"设计接口（防重放/幂等/对账视角） | 用户原始叙事（不同管理方 + 充电免停）的技术化表达；伪微服务（同认证/同库/单机部署的进程切）是负资产：无独立伸缩/部署收益却背分布式成本；进程边界不产生信任边界——信任边界靠协议设计；演进拆分条件未到（详见总体计划） |
| 空间模型共享 | 车位主数据仍在 parking（park_space）；charging 新增 `charging_pile` 绑 `space_id`，**不重建空间表** | 车位是共享物理资源；避免两套空间 CRUD 的体积重复；桩→车位→停车会话的锚定链自然成立 |
| 计费各域自治、范式统一 | charging 自持计费纯函数（电量×电费单价+服务费），不抄 FeeCalculator 代码；范式继承：纯整数分存储/纯函数/边界防御/单测矩阵 | 时长计费与电量计费不同构（领域本质）；跨上下文共享内核破坏限界上下文自治；范式复用不是代码复用 |
| 免停权益 = 1 张 | 单权益单次核销；有效期制；减免语义与取整先后在 M1-1 拍板 | M1 窄而深；叠加/多张规则 M2 优惠引擎 |
| 调度 = M1 真需求 | 4 job：权益过期作废/充电会话超时巡检/长期占用巡检/跨方对账 | 权益过期纯时间驱动（无调度即永不失效）；充电会话悬挂需巡检；跨方协作必然对账——Quartz 从空转转正，触发壳子 Quartz 治理升级项（roadmap 表） |
| 支付语义不进 M1 | 订单"生成即完结"（M0 同构） | 停车 M0 已免支付；充电补支付需同步补停车支付，范围爆炸；对账仍是真实需求（跨方对账 ≠ 支付对账） |

## 4. 领域对象草案（字段级 M1-1 定稿 2026-09-05）

- `charge_fee_rule` 充电费率：rule_id、rule_name、电费单价 fen/kWh、服务费单价 fen/kWh、启停、备注、创建时间——**新表不扩 fee_rule**（计费各域自治）；M1 固定价预置一条（电费 80 + 服务费 40 fen/kWh）
- `charging_pile` 充电桩：pile_id、桩编号(唯一)、绑车位 space_id(唯一 1:1)、状态(0空闲/1充电中/2停用)、创建人/创建/更新时间
- `charge_session` 充电会话：session_id、桩 id/车位 id/车牌、anchor_session_id(锚定停车会话，start 时定死)、start/end 时间、总电量 Wh、状态(0充电中/1已结束/2已取消/**3超时结束**)、取消原因、创建/更新时间
- `charge_order` 充电订单：order_id、会话 id(唯一)、快照(桩号/车位/车牌/起止/energy_wh/两单价/两段金额/amount_fen)、状态(0已生成)、创建时间
- `benefit_record` 免停权益：benefit_id、权益码 benefit_no(唯一=凭证码 BN+时间戳+随机)、来源充电订单 id、车牌、anchor_session_id(继承自充电会话锚定)、free_seconds(秒)、expire_time、状态(0可用/1已核销/2已过期)、核销会话/订单 id、签发/核销时间
- `park_order` 扩展：+discount_fen +benefit_no（减免快照；amount_fen 保持应收原义，实付=应收−减免可推导不入库）

**电量与金额口径**：电量存整数 Wh；两段单价 fen/kWh；段金额各自四舍五入到分 `(Wh×单价+500)/1000`，总额=电费金额+服务费金额（快照恒等）；0 Wh 不发权益。

状态机（充电会话）：`充电中 → 已结束 | 已取消 | 超时结束`（终态不可逆，判官同 parking；超时结束=巡检强制，0 电 0 元订单）
状态机（权益）：`可用 → 已核销 | 已过期`（核销=条件更新判官；过期=调度 job 条件更新）

## 5. 接口面草案

管理端（权限串前缀 `charge:xxx`、`park:order/benefit`，注册 sys_menu 3xx）：
- 桩列表/绑定；充电会话/充电订单/权益记录分页查询（只读最小面）

设备/开放端（X-Device-Token 通道扩展 `/device/charging/*` 或复用现有通道语义）：
- `POST /device/charging/start`（桩编号/车位/车牌 → 充电会话，若该车位停车中则自动锚定停车会话）
- `POST /device/charging/finish`（会话 → 电量上报 → 订单 + 权益签发）
- `POST /device/charging/cancel`（充电中止撤销）

device-sim：新增 PILE-001~003 绑 B-001~003 车位 + 手控事件（start/finish/cancel，finish 携带总电量）+ 充电剧本。

调度（Quartz）：权益过期扫描（每分钟）、充电会话超时巡检（断连悬挂强制终态+算费）、长期占用巡检（报警/标记）、跨方对账（签发 vs 核销差异清单，日志+管理端可见）。

## 9. M1-1 讨论定稿（2026-09-05）

1. **字段级/单位口径**：电量 Wh 整数；单价 fen/kWh；段金额各自 `(Wh×单价+500)/1000` 四舍五入到分再相加（快照恒等）；权益 free_seconds 秒；费率表 = 新表 charge_fee_rule（不扩 fee_rule）
2. **权益锚定**：start 时必须锚定该车位进行中停车会话（无则拒绝充电开始），车牌一致校验（防凭证错配）；benefit.anchor_session_id 从充电会话继承；0 Wh 不发权益
3. **减免算法**：应收原公式不变；减免 = `(free_seconds×单价)/3600` floor 到分；实付 = max(0, 应收−减免)；amount_fen 原义 + discount_fen/benefit_no 快照，实付可推导不入库；核销与出场结算同事务双判官（会话终态化 + 权益条件核销 WHERE benefit_no=? AND state=0 AND anchor_session_id=?）
4. **凭证协议**：权益码 BN+yyyyMMddHHmmss+6 随机，唯一索引；签发在 charging 域 finish 事务内；核销 = parking 调 charging 能力接口（ChargingBenefitService.redeem），parking 不直连 benefit 表；不加事件广播（M1 无消费方，对账 job 兜底）；核销失败（错配/过期/已核销）→ 按无减免结算 + warn 告警，不挡出场
5. **调度与治理**：权益过期（每分钟批条件更新）；充电会话超时巡检（默认 2h → state=3 超时结束 + 0 电 0 元订单 + 不发权益 + 告警）；长期占用巡检（超 3 天告警不动账）；跨方对账（每小时：成功单必有权益/核销 vs 快照一致，差异清单日志+管理端）。治理：统一 job 骨架（traceId+异常日志）+ 条件更新幂等 + 简单 misfire 恢复；不做执行历史表/告警通道（M2/M4）
