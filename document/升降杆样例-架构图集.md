## 1. 系统上下文与进程拓扑

```mermaid
graph LR
    ADMIN["管理员 / 运维<br/>HTTP token（/api/**）"] --> MAIN["reason-main :8200<br/>平台（Spring Boot 3）"]
    SIM["reason-barrier-sim :8300<br/>虚拟升降杆 50 台<br/>密钥=本地文件（仓库零明文）"] -->|"心跳 HTTP（恒）<br/>事件 MQ 默认 / HTTP 降级"| MAIN
    MAIN -->|"下行指令 HTTP<br/>per-device HMAC + QUERY_STATE"| SIM
    SIM -->|produce| MQ["RocketMQ<br/>namesrv:9876 / broker:10911 / proxy:8081"]
    MQ -->|"consume（单并发，保序）"| MAIN
    MAIN <--> MY[("MySQL 8<br/>reason_faster")]
    MAIN <--> RD[("Redis<br/>dev=db15")]
```

- 云部署形态=单机六进程（MySQL + Redis + MQ 三进程 + main + sim，见部署手册）；本地=双进程 + 本机中间件。
- 通道三态（D-A）：`sim.event-channel=mq（默认）| http | dual`；心跳恒 HTTP（D3：判活不依赖 broker）；下行恒 HTTP。
- 安全边界：管理端=token + RBAC；设备面=per-device HMAC（上行验签 + 下行签名，事件与心跳双通道同权）。

## 2. 手动抬杆指令闭环（时序）

```mermaid
sequenceDiagram

    participant P as 平台
    participant D as sim 设备
    A->>P: POST /api/device/command/open
    Note over P: @RepeatGuard（3s 防连点）→ @SysLog 留痕 → @ManualHold（受理后写入保持期）
    P->>D: POST /cmd（HMAC 签名 + X-Trace-Id）
    D->>D: 验签 → seq 幂等（已执行 / 已拒绝双线）→ 受理进入 MOVING
    D-->>P: code=0 受理
    P->>P: command_log = PENDING
    D->>P: 到位事件（commandSeq + bootId + eventSeq，HMAC 签名）
    Note over P: 验签 → 序守卫 → 按 commandSeq 精确销账
    P->>P: 流水 ARRIVED + 台账条件更新（单写铁律）
    alt 超时未到位（60s）
        P->>D: QUERY_STATE 查询实况
        D-->>P: 状态 + lastEventSeq + 最近指令结果
        P->>P: 按实况决策（重试 / 告警 / 放行）——替代"查自己旧快照"
    end
```

## 3. 事件上行双通道数据流

```mermaid
flowchart LR
    EV["sim 事件生成（traceId 起点）"] --> ROUTE{"sim.event-channel"}
    ROUTE -->|"mq（默认）"| PROD["producer 单发送线程保序<br/>失败队首持留 + 退避 1-5s<br/>队列满丢最旧记 error"]
    ROUTE -->|"http（降级）"| HTTPIN["HTTP 入口 /device/event"]
    ROUTE -->|"dual（对照期）"| PROD
    ROUTE -->|"dual（对照期）"| HTTPIN
    PROD --> TQ["topic: device-event<br/>单读写队列（全局有序 D5）<br/>property: 设备号+签名+traceId"]
    TQ --> CONS["SimpleConsumer 单并发<br/>毒消息 ack 丢弃 / 瞬时异常重投→死信"]
    HTTPIN --> GUARD["DeviceTrafficGuard<br/>per-device 5rps + 全局闸 100rps"]
    GUARD --> AUTH
    CONS --> AUTH["DeviceChannelAuthenticator<br/>验签（复用同一实现）"]
    AUTH --> SVC["DeviceEventService<br/>序守卫（bootId+eventSeq）/ 按 seq 销账"]
    SVC --> DB[("流水 + 台账<br/>CAS 跃迁 + 单写铁律")]
```

- 幂等吸收：重复投递由业务层（序守卫 + 按 seq 精确销账）吸收，consumer 不做额外去重。
- 位置：HTTP 入口限流在验签之前；MQ 路径的保护=broker 持久化 + 单并发消费 + sim 保序队列。

## 4. 告警生命周期

```mermaid
flowchart LR
    SRC["异常源<br/>离线/故障/超时/漂移/停摆"] --> DEDUP{"SETNX 去重<br/>300s 窗口"}
    DEDUP -->|"已存在"| SKIP1["跳过（持续异常周期提醒）"]
    DEDUP -->|"新告警"| RATE{"滑动窗口限速<br/>per-type 10 条/60s"}
    RATE -->|"超限"| SKIP2["只记 warn 日志不落库<br/>（回滚去重占位）"]
    RATE -->|"通过"| DB[("device_alarm<br/>handled=0 未处理")]
    BATCH["单轮离线 ≥3 台"] --> MERGE["合并 1 条 BATCH_OFFLINE<br/>（离线回落自动关，谁开谁关）"]
    MERGE --> DB
    DB -->|"人工确认"| HANDLED["handled=1 + 处理人 + 时间<br/>（@SysLog 留痕）"]
    DB -->|"恢复路径自动关"| CLOSED["关闭"]
    CLOSED -.->|"心跳恢复"| DB
    CLOSED -.->|"事件到位"| DB
    CLOSED -.->|"校正闭环"| DB
```

- 四类恢复关闭路径：心跳恢复关 OFFLINE / 事件到位关 MOVING_STUCK / 校正闭环关 AUTO_CORRECT_FAILED / 批量离线谁开谁关。
- 任务看护独立通道：job 停摆 → ERROR 日志 + JOB_STALLED（每任务独立去重键）。

## 5. 设备状态机与治理闸

```mermaid
stateDiagram-v2
    [*] --> DOWN : 心跳自述 / 事件
    DOWN --> MOVING : 受理指令（seq 幂等）
    UP --> MOVING : 受理指令（seq 幂等）
    MOVING --> UP : 到位事件（OPEN）
    MOVING --> DOWN : 到位事件（CLOSE）
    DOWN --> UP : 到位事件（OPEN）
    UP --> DOWN : 到位事件（CLOSE）
    DOWN --> FAULT : FAULT 事件 / 心跳
    UP --> FAULT : FAULT 事件 / 心跳
    MOVING --> FAULT : FAULT 事件 / 心跳
    FAULT --> DOWN : 人工复位（recover）
```

码值：`UP=1 / DOWN=2 / MOVING=3 / FAULT=4`（device_record.device_state）。

治理闸（围绕状态机叠加，不改变状态机本身）：

| 机制 | 作用点 | 一句话语义 |
|---|---|---|
| AutoTask 四道仲裁 | 自动升降下发前 | 保持期让位 → 离线跳过 → MOVING 跳过 → 应然已满足跳过 |
| MonitorTask 重试 | PENDING 超时 | 复用仲裁 + 代际裁决（旧代际 SUPERSEDED）；先 QUERY_STATE 再决策 |
| 熔断 | 连续 N 次校正未闭环 | 停自动 + AUTO_CORRECT_FAILED 告警（平台观测连续失败，非设备自认） |
| MOVING 巡检 | 台账卡 MOVING 超阈值 | 告警转人工（只喊不改状态） |
| 手动保持期 | 手动指令受理后 30min | 自动规则让位（DB 双写，Redis 丢失可重建） |

## 6. 事故三分段定位（MQ 形态）

```mermaid
flowchart LR
    S["sim 事件生成<br/>①生成 traceId"] -->|"②produce"| B["broker device-event<br/>持久化 / 积压"]
    B -->|"③consume"| C["平台消费线程<br/>④traceId 落 MDC"]
    C -->|"⑤处理"| DB[("流水 / 台账 / 告警")]
    S -. "锚点：sim-logs 上报日志<br/>（发送失败/队首持留/退避）" .-> S
    B -. "锚点：consumerProgress 积压 diff<br/>%DLQ% 死信" .-> B
    C -. "锚点：平台日志 [MQ事件消费]+traceId<br/>序守卫拒绝原因" .-> C
    DB -. "锚点：三表互证<br/>（台账/流水/告警）" .-> DB
```

- 判定手法：同一 traceId 在 sim 日志 / broker 积压 / 消费日志 / DB 落值四处可核对——断在哪一段由"traceId 消失的位置"判定。
- 兜底：任务看护（JOB_STALLED）发现"静默停摆"（数据库说启用、实际没跑）。
- 对应事故模型：sim→broker 断 / broker 故障 / 消费积压（批次4 三分段手法落档）。
